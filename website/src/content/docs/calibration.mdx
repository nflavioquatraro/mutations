## What this part does

Calibration turns frozen hidden-state features and measured route outcomes into
router scores that have an operational meaning. It owns the offline data,
fitting, calibration, refinement, and oracle contracts; it does not execute
model paths or silently change a live registry.

<IntegrationBadge status="Integrated" />

The primary end-to-end path is feature bank → utility labels → independent
ridge heads → held-out temperature and threshold calibration → immutable
router-bearing package. Pair-aware and registry-wide methods are implemented
and validated as explicit composable workflows.

## Where it fits

Calibration connects expert training to package installation:

1. a frozen router feature extractor produces pre-MLP features;
2. an external deterministic evaluation loop measures anchor and expert losses;
3. aligned banks bind those measurements to stable row, layer, and expert IDs;
4. offline fitting produces frozen router heads;
5. held-out calibration gives score scale and activation thresholds meaning;
6. package derivation publishes a new immutable specialization version;
7. registry synchronization later attaches those artifacts to a model.

The calibration package never downloads a model, captures hidden states through
hooks, executes counterfactual paths, installs a package, or mutates an
incumbent router in place.

### Immutable feature banks

`RouterFeatureBank` stores one finite CPU design matrix for every converted
layer. All matrices share the same row count, feature size, dtype, and unique
non-negative row IDs. Dataset identifier, exact revision, split, filters,
collection seed, feature specification, tensor digests, and a canonical
metadata hash make the bank auditable without storing prompts.

The version-one format uses non-executable safetensors. Save and load reject
unsafe paths, accidental overwrites, unexpected tensors, incompatible feature
spaces, malformed metadata, and digest mismatches.

### Domain and utility labels

`DomainLabelBank` stores deterministic categorical targets. It sorts unique
class names lexicographically, so class indices do not depend on encounter
order.

`UtilityLabelBank` stores continuous anchor-relative utility for each
layer-expert column. Its row IDs and feature-bank metadata hash must exactly
match the feature bank; expert columns use the same stable order expected by
append-only router heads.

Domain labels and utility labels are intentionally different types. The
current ridge fitter accepts utility labels only; it does not silently reinterpret
domain classes as regression targets.

### Independent ridge heads

`fit_independent_ridge()` fits all expert utility columns for one layer in a
single deterministic CPU float64 solve. Features and targets are centered, so
the positive ridge penalty regularizes weights while leaving the intercept
unregularized.

The result is an `AppendOnlyRouterHeads` object with one frozen affine head per
layer and expert. Parameters are copied to the feature-bank dtype, ordered
deterministically, and rejected if reduced-precision deployment would produce
non-finite state.

### Temperature and activation thresholds

`calibrate_temperature_and_thresholds()` requires a separate held-out bank and
two explicit, non-empty, disjoint row partitions:

- temperature rows fit one positive scale per head against the binary
  positive-utility target;
- threshold rows choose the most sensitive activation boundary that satisfies
  the requested false-activation budget.

The method never mutates the ridge heads. It returns independent frozen heads
and a JSON-compatible report containing row partitions, metrics, fallbacks,
temperatures, and thresholds. Single-class partitions have explicit
deterministic fallback behavior.

### Immutable package handoff

`derive_calibrated_router_package()` binds already fitted and calibrated heads
to their exact fitting and calibration bank identities. It verifies globally
disjoint data IDs, feature topology, expert order, head ownership, dtype,
report contents, and source-package payload hashes.

The source expert-only package remains byte-for-byte unchanged. The output is a
new immutable version with router payload, thresholds, calibration provenance,
and runtime metadata. No fitting or hidden registry synchronization occurs
during derivation.

### Pair utility and route oracles

`plan_expert_pairs()` can enumerate every expert pair explicitly or choose a
deterministic bounded subset without materializing the full pair universe.
`compute_pair_utilities()` aligns supplied anchor, single-expert, and pair
losses with that plan and records:

- gain over the anchor;
- improvement over the best individual expert;
- stable best-pair targets;
- an optional strict mixture-improvement mask.

`CounterfactualRouteLosses` stores the anchor first, then every single expert,
then the evaluated sparse pairs. `evaluate_counterfactual_oracle()` compares a
selected route with the first minimum-loss candidate in that canonical order.
It evaluates supplied losses; it does not run experts or claim that an
unevaluated pair is suboptimal.

### Explicit refinement and recalibration

`refine_stability_margins()` adjusts newly calibrated candidate affine state
against the fixed-zero anchor and an optional frozen incumbent score bank.
Separate stability rows protect incumbent behavior while positive-utility win
rows encourage the candidate to clear a declared margin. Temperature,
threshold, ownership, and append order stay fixed.

`recalibrate_global_router()` is a separate registry-wide mode. It jointly
refits one frozen logical router against anchored best-route targets, preserves
column order and calibration metadata, and returns a new registry-bound router
version. It never activates that router automatically.

`fit_learned_mixture_head()` consumes caller-supplied oracle pair weights
aligned to a CAL-003 plan. The learned head controls interpolation between an
already selected pair; it does not change which experts were selected.

## How it works

The integrated anchored top-1 workflow keeps three data boundaries visible:

```text
Fitting rows
  → feature bank + utility labels
  → frozen ridge heads

Held-out calibration rows
  → temperature partition + threshold partition
  → frozen calibrated heads + report

Immutable package boundary
  → expert-only package + exact bank identities
  → new router-bearing package version
```

Fitting and calibration rows must be globally disjoint before the package is
published. Later pair, stability, or registry-wide experiments use explicit
additional inputs and produce new artifacts rather than modifying this history.

## Minimal usage

Fit utility heads and calibrate them on explicitly partitioned held-out rows:

```python
fitted = fit_independent_ridge(
    fitting_bank,
    fitting_utilities,
    regularization=1e-3,
)
calibrated, report = calibrate_temperature_and_thresholds(
    fitted, held_out_bank, held_out_utilities,
    temperature_row_ids=temperature_rows,
    threshold_row_ids=threshold_rows,
    false_activation_rate=0.01,
)
```

The fitting and held-out banks must have compatible feature specifications but
different row identities.

## Current limitations

- Feature and label formats are unsharded, in-memory, and CPU-oriented. They
  have no streaming writer, memory mapping, compression, or distributed merge.
- Model hooks, hidden-state collection, forced-path counterfactual execution,
  and automatic dataset splitting remain caller-owned workflows.
- Ridge fitting accepts aligned utility targets only. Domain-target fitting,
  weighting, incremental updates, and accelerator fitting are unsupported.
- Temperature calibration is independent per head and binary. It does not
  provide joint multiclass confidence calibration or confidence intervals.
- Threshold fitting requires explicit disjoint partitions. It controls the
  observed held-out false-activation rate, not a population guarantee.
- Stability refinement changes affine parameters without re-enforcing the
  earlier CAL-005 false-activation budget; its new report becomes
  authoritative.
- Pair planning stores no persistent pair-utility bank and cannot assess
  unevaluated pairs. Counterfactual model execution and learned oracle mixture
  weights remain external.
- Global recalibration has no pair-aware top-2 objective and never activates
  its output automatically.
- Package-driven top-2 attachment, mixed precision, multi-device fitting, and
  production-scale Qwen3 calibration remain future validation work.

regression estimator.

non-executable bank and router formats.

integrity primitive used for canonical metadata and tensor digests.

project-specific framework mechanisms rather than algorithms attributed to a
paper. Their objectives, deterministic choices, ownership boundaries, and
