## What this page does

These guides connect the framework's individual strategies into inspectable
workflows. They begin with the conservative dense-equivalence baseline and will
progress toward package installation, weighted mixtures, adaptive computation,
delta experts, local training, and hierarchical routing.

The comparison table includes the planned workflow set so that integration
boundaries are visible from the start. This first published slice documents
only the exact anchor conversion; later rows remain clearly marked as upcoming
guides.

## Exact anchor conversion

<IntegrationBadge status="Integrated" />

### The problem it solves

Before adding specialists, conversion must prove that wrapping selected dense
MLPs does not change the model. This workflow creates a tiny local Qwen3 model,
records its outputs, converts the upper-half MLPs to routed wrappers, and
compares the result with zero tolerance.

### Workflow contract

- **Expert representation:** none; the original dense MLP remains candidate
  zero.
- **Routing and selection:** every converted wrapper starts in
  `forced_anchor`, so no router score is evaluated.
- **Combination and capacity:** the anchor output is returned directly;
  specialist mixing and overflow handling are inactive.
- **Training and calibration:** neither is required.
- **Active work:** one anchor MLP per token at every converted layer.
- **Packaging and serialization:** no expert package is created. The example
  validates conversion before package lifecycle work begins.
- **Expected result:** every hidden state and final logit is exactly equal on
  the deterministic CPU fixture.

### How it runs

```text
Tiny local Qwen3 anchor
  → record dense hidden states and logits
  → wrap upper-half MLPs in forced-anchor mode
  → execute the same input
  → require exact tensor equality
```

The wrapper retains the same original MLP object as `anchor_mlp`. The
integration test also fingerprints its parameters before conversion and
requires that fingerprint to remain unchanged.

### Run the verified example

From the repository root, run:

```bash
python examples/verify_dense_equivalence.py
```

The workflow is offline: it constructs a deterministic random model and
downloads neither weights nor tokenizer data. A successful run reports layers
`(2, 3)`, exact logits, and a maximum absolute difference of `0.0`.

<CodeDisclosure
  summary="Show the core exact-equivalence check"
  source="examples/verify_dense_equivalence.py"
  verified
>

```python
with torch.no_grad():
    dense = model(input_ids=input_ids, output_hidden_states=True)

report = Qwen3Backend().convert(
    model,
    AnchoredMoEConfig(converted_layers="upper_half"),
)

with torch.no_grad():
    converted = model(input_ids=input_ids, output_hidden_states=True)

assert_tensors_equivalent(converted.logits, dense.logits, name="logits")
```

Expected invariant: final logits are exactly equal. The linked example also
checks every hidden state; the
[`test_qwen3_equivalence.py`](https://github.com/nflavioquatraro/mutations/blob/main/tests/integration/test_qwen3_equivalence.py)
integration test verifies zero-tolerance equality, object identity, and the
unchanged anchor fingerprint.
</CodeDisclosure>

### Current limitations

- The fixture proves framework equivalence, not language quality.
- Qwen3 is the only currently validated backend.
- Exact equality is established for the deterministic CPU path. Optimized
  kernels, reduced precision, and other runtimes require separate validation.
- No specialist, router, package, calibration artifact, or composition
  checkpoint exists yet; those belong to subsequent workflows.
