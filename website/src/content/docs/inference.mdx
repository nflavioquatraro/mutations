## What this part does

Inference turns frozen router scores and expert modules into token outputs. The
primary runtime selects the immutable anchor or one specialist for every token,
executes only the required paths, and reconstructs the original token order
without dropping work.

<IntegrationBadge status="Integrated" />

The complete package-to-model path is integrated for full-MLP experts,
independent affine heads, and anchored top-1. Installation remains a registry
operation; `synchronize_registry()` is the explicit boundary that changes
model execution.

## Where it fits

Inference is the last stage of the package lifecycle:

1. training produces frozen expert payloads;
2. calibration adds immutable affine router heads;
3. the registry validates packages and records their stable active order;
4. explicit synchronization materializes those payloads into routed layers;
5. each routed layer scores, selects, dispatches, and reconstructs tokens;
6. optional telemetry summarizes the routes that actually executed.

The inference package does not install packages implicitly, fit routers,
estimate serving capacity, or change expert weights. Registry state may move
ahead of runtime state until the caller deliberately synchronizes the model.

### Package-driven anchored top-1

PKG-007 reads explicit `(layer, expert ID, payload)` bindings from every active
package. It validates the complete intended runtime first, materializes
full-MLP experts against their immutable layer anchors, and compiles
package-owned affine heads into one frozen logical score bank per layer.

Only after every layer passes validation does synchronization replace the
current routed runtime. Active package order and package-local router order
determine expert append order, so equal-score ties and later audit reports are
deterministic.

### Sparse dispatch and reconstruction

For each routed layer, INF-001 applies anchored hard top-1 selection and
availability fallback. Candidate zero is always the anchor. Positive candidate
indices map to experts in stable router order.

Tokens are flattened only across their token-leading dimensions, grouped by
effective route, and gathered into one sparse call per non-empty candidate.
`torch.index_copy` then restores every output to its original token position.
Inactive experts are never executed, and overflow always returns to the anchor.

### Explicit synchronization and exact removal

`model.install()` and `model.unload()` change the active registry, not the
already configured routed layers. `model.synchronize_registry()` is the
separate operation that applies the complete registry snapshot.

Synchronizing an empty registry clears loaded experts and router heads and
restores the exact forced-anchor path. Reinserting the same immutable package
into its historical slot and synchronizing again restores the same registry
identity and routed behavior.

### Privacy-safe route telemetry

`RouteTelemetry` is an optional bounded in-memory recorder for direct anchored
top-1 attachment. Each record contains the layer, selected and effective
candidate indices, selected scores, overflow flags, and stable expert IDs.

Records are detached, cloned to CPU storage, and capped by invocation count.
They deliberately exclude token IDs, token text, hidden states, logits, and
expert activations. Summaries expose only anchor, expert, overflow, token, and
invocation counts.

### Advanced composable paths

The inference package also validates standalone top-2 dispatch, hierarchical
preselected pairs, always-on anchor-relative deltas, and two-expert LoRA
parameter merging. These modes preserve explicit fallback and ordering
contracts, but package-driven attachment and declarative model configuration
remain future work.

## How it works

The integrated runtime has two deliberately separate transitions:

```text
Active registry snapshot
  → validate every package, payload binding, and router key
  → build every layer runtime without changing the model
  → atomically apply the complete synchronized runtime

Hidden states at one routed layer
  → frozen feature extraction and router scores
  → anchored top-1 plus availability fallback
  → sparse anchor or expert execution
  → deterministic output reconstruction
  → optional bounded route record
```

That separation prevents a partially valid package collection from changing
only some layers. It also makes stale registry/runtime state observable instead
of silently repairing it during a forward pass.

## Minimal usage

Install a validated package, then explicitly apply the new registry snapshot:

```python
package = ExpertPackage.from_directory("./code-experts")
model.install(package)
report = model.synchronize_registry()

output = model(input_ids=input_ids)
assert report.configured_layers == model.config.resolved_converted_layers
```

Installing the package alone does not alter the forward path. The call to
`synchronize_registry()` is what materializes and applies anchored top-1
execution.

## Needle request-level execution

[Needle cached generation](/docs/needle-branches/#generate-with-an-incremental-kv-cache)
routes once per response, shares one JAX prefix prefill, and reuses incremental
KV state while decoding. `use_cache=False` remains the full-history parity
path. This execution is owned by `BranchedModel`, independently of registry
synchronization and MLP dispatch.

[Browser deployment](/docs/browser-deployment/) reconstructs complete `.cact`
models from one base and lazy router/specialist patches, then runs each through
the official WASM runtime. The generative router sees recent context. Downloads
share base bytes; native weights, prefill, and KV caches remain separate.

## Current limitations

- Package-driven synchronization supports complete full-MLP experts,
  identity features, independent affine heads, and anchored top-1 only.
- Route telemetry is opt-in for direct top-1 configuration. Package
  synchronization does not attach a recorder automatically, and top-2
  telemetry is not implemented.
- Standalone top-2, hierarchical pair dispatch, anchor-relative deltas, and
  parameter-space LoRA merging are validated composable paths rather than
  package-driven model modes.
- Capacity is supplied as explicit availability. The runtime does not estimate
  load, search beyond an unavailable selected route, or manage distributed
  all-to-all execution.
- Token-aligned auxiliary MLP arguments, optimized batched grouping,
  multi-device materialization, and production serving kernels remain future
  work.
- Telemetry is process-local and in-memory. It is not a persistent route log
  or distributed aggregation service.

## References

The [architecture paper](/paper.pdf) and repository blueprint listed in the
page sources define the fixed-zero anchor, deterministic routing,
no-token-dropping rule, capacity fallback, and reference top-1 execution
policy.

[PyTorch `index_select`](https://docs.pytorch.org/docs/stable/generated/torch.index_select.html)
defines sparse token gathering, while
[`index_copy`](https://docs.pytorch.org/docs/stable/generated/torch.index_copy.html)
defines differentiable reconstruction in original token order.
[`ModuleList`](https://docs.pytorch.org/docs/stable/generated/torch.nn.ModuleList.html)
provides stable expert registration without encoding expert IDs as attribute
names.

INF-001, PKG-007, CORE-005, and EVAL-002 are project infrastructure rather
than paper-derived training or optimization algorithms. Their behavior follows
the repository’s immutable-anchor architecture and the cited PyTorch tensor
contracts.
