## What this part does

Routers turn a token's pre-MLP hidden state into calibrated evidence for each
installed specialist. They preserve stable expert ordering and package
ownership, but they do not decide which path runs or execute an MLP.

<IntegrationBadge status="Integrated" />

The core identity-feature, independent-head, and logical-router pipeline is
integrated into package-driven anchored top-1 composition. Global
recalibration and distillation are explicitly composable, while hierarchical,
shortlisted, and cross-layer strategies remain research primitives.

## Where it fits

The router is one stage in a deliberately separated runtime:

1. a converted layer exposes the hidden state immediately before its MLP;
2. a frozen feature extractor produces the router feature tensor;
3. package-owned heads score their experts;
4. a logical router presents those scores in stable registry order;
5. a selection policy compares specialist evidence with the zero-score anchor;
6. inference dispatches the selected experts and combines their outputs.

The routers subpackage owns stages two through four. Calibration fits or
adjusts head parameters, policies choose routes, capacity rules handle
availability, inference executes sparse paths, and the registry controls
package lifecycle.

### Frozen identity features

`IdentityRouterFeatureExtractor` accepts the pre-MLP hidden state and returns
the same tensor object. Version one has no learned projection, allocation, or
hidden detachment. This keeps the feature space easy to audit and lets the
caller control gradient flow during explicit fitting.

The extractor also exposes an immutable feature specification. Packages bind
their heads to that specification so a router trained for one hidden width or
feature transformation cannot be attached silently to another.

### Independent append-only heads

Each `AffineRouterHead` owns one expert score at one decoder layer. Its affine
weight and bias produce raw evidence; a positive temperature and a threshold
turn that evidence into the calibrated score consumed by later policies.

`AppendOnlyRouterHeads` preserves registration order and rejects duplicate
`(layer_index, expert_id)` ownership. Appending a package does not rewrite old
heads, and the safetensors format contains only finite tensors and validated
non-executable metadata.

### One frozen logical router

`compile_logical_router()` copies independent package heads into a
`LogicalAppendOnlyRouter`. The runtime stores layer-local affine rows,
temperatures, and thresholds as frozen buffers while preserving the same score
shape, expert identifiers, and calibrated values.

Compilation is an ownership boundary: later training of a package head cannot
change the deployed router. The implementation evaluates columns in a
shape-stable order so appending a new column preserves every incumbent score
bit-for-bit for identical inputs, dtype, device, and backend.

### Explicit global recalibration

`recalibrate_global_router()` jointly fits copied affine columns against an
aligned replay bank of anchor-relative utilities. It returns a new frozen
logical router and a report bound to the exact registry and compatibility
hashes; source heads, experts, and model state remain unchanged.

This mode intentionally gives up append-only score invariance. It never runs
as a hidden installation side effect, and activating its separately persisted
registry-router version remains an explicit lifecycle operation.

### Hierarchical package and local scoring

`HierarchicalRouterScoreBank` scores packages first, then evaluates a local
logical router only for token rows assigned to the selected non-anchor
package. Stable flattened row indices let the policy reconstruct the original
token shape without scoring unrelated local experts.

The current hierarchy requires rectangular layer coverage, at least two local
experts per package, and globally unique expert identifiers. It is constructed
manually from validated logical routers and has no manifest-driven model
attachment.

### Prompt-level shortlisting

`PromptTopMShortlister` accepts external finite retrieval scores and selects a
stable top-M candidate set for each prompt. A
`PromptShortlistedLogicalRouter` evaluates only those columns, then restores
the complete expert dimension with a finite value below the zero-score anchor
for every unselected candidate.

The retriever, its training, generation-time reuse, and expert-weight paging
are outside this primitive. A retrieval miss therefore cannot be recovered by
the token router unless another shortlisted specialist has positive evidence.

### Router distillation

`distill_frozen_router()` takes an immutable teacher score bank, derives
anchor-first hard top-1 assignments over cached features, and fits a
deterministic affine student. The accepted student compiles into the ordinary
frozen logical-router contract, so explicit routed-layer composition needs no
distillation-specific dispatcher.

Version one distills assignments rather than score distributions. It does not
yet cover top-2 or adaptive targets, persist its report with a registry
version, or activate itself on a model.

### Cross-layer route stickiness

`CrossLayerTop1Stickiness` applies a switching margin between the current
anchored top-1 winner and a caller-supplied previous-layer route. It compares
both candidates using current-layer evidence and retains the incumbent unless
the new winner exceeds it by strictly more than the margin.

The stabilizer owns no request state. A model or generation loop must carry
the previous route explicitly; zero margin delegates exactly to ordinary
anchored top-1 behavior.

## How it works

### Keep score production separate from route choice

Router output has one specialist column per registered expert. The permanent
anchor column is not stored in the router because its evidence is always zero.
A selection policy prepends that zero conceptually and applies anchor-first,
stable tie-breaking.

This boundary matters: a positive specialist score is evidence, not an
execution command. Top-1, top-2, adaptive, compatibility, and capacity
policies can interpret the same score bank differently.

### Preserve ownership through compilation

Package files retain independently owned affine heads because installation,
removal, and versioning operate at package boundaries. The synchronized model
uses a compiled logical view because inference needs one stable expert order
per layer.

Compilation copies rather than aliases state:

```text
Package heads → validated append order → copied frozen buffers → score bank
```

The logical architecture is therefore an in-memory runtime representation, not
a second package wire format.

### Make advanced behavior explicit

Global recalibration may change all scores, hierarchical routing changes which
columns are evaluated, shortlisting depends on external prompt evidence,
distillation approximates a teacher, and stickiness depends on a previous
decision. Each behavior has a separate public entry point and records or
returns the metadata needed to audit its boundary.

## Minimal usage

Compile one package-owned affine head into a frozen logical score bank:

```python
from anchored_moe import AffineRouterHead, AppendOnlyRouterHeads
from anchored_moe import compile_logical_router

heads = AppendOnlyRouterHeads(feature_size=4096)
heads.append(AffineRouterHead(
    4096, layer_index=18, expert_id="code:0"
))
router = compile_logical_router(heads)
scores = router(hidden_states, layer_index=18)
```

The resulting final dimension follows stable expert order. Comparing these
scores with the anchor and executing a path remain separate policy and
inference steps.

## Current limitations

- Version-one runtime features are the identity transform; there is no learned
  frozen projection.
- Logical compilation deliberately favors bit-exact append invariance over one
  fused matrix multiplication and has no independent package format.
- Global recalibration requires aligned offline replay data and changes every
  specialist score for one exact registry.
- Hierarchical routing requires rectangular package topology and explicit
  construction from logical routers.
- Prompt shortlisting requires caller-provided retrieval scores and does not
  retain generation state or page expert weights into memory.
- Hard-route distillation supports anchored top-1 assignments only and has no
  report-bearing registry activation.
- Cross-layer stickiness is caller-sequenced outside the model forward; it does
  not provide top-2, adaptive, or autoregressive hysteresis.
- Selection, combination, capacity, dispatch, feature caching, calibration,
  and package lifecycle remain deliberately separate subsystems.
